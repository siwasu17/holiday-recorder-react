## Context

現在のカテゴリ定義は `color` プロパティのみを持っており、これはライトモード用に調整されたパステルカラーである。ダークモード導入後、これらの色が背景に対して明るすぎて浮いて見えるという課題が発生している。

## Goals / Non-Goals

**Goals:**
- 各カテゴリにダークモード用の色（`darkColor`）を定義する。
- テーマ設定に応じて、適切な色を動的に選択するロジックを実装する。
- ダークモード時のテキストの視認性を向上させる。

**Non-Goals:**
- ユーザーがカスタムカラーを定義できる機能の追加。
- カテゴリ自体の追加や削除。

## Decisions

### 1. データモデルの拡張
- `Category` インターフェースに `darkColor: string` を追加する。
- これにより、型安全にライト/ダーク両方の色を管理できる。

### 2. カラーパレットの選定
探索フェーズで検討した以下のパレットを採用する。
- 背景色 `#121212` に馴染むよう、明度を下げ、彩度を調整した深みのある色を使用する。

### 3. 色選択のロジック
- `useThemeContext` を使用して現在のテーマを取得する。
- `isDark` フラグを作成し、三項演算子等で `category.darkColor` と `category.color` を切り替える。
- タイムスロット表示（`TimeTracker.tsx`）およびカテゴリ選択画面（`CategoryGrid.tsx`）の両方に適用する。

### 4. テキスト色
- ダークモード時は背景が濃くなるため、カテゴリ名等のテキスト色は明るい色（`#E0E0E0` 等）に固定、またはテーマに応じた変数を使用する。

## Risks / Trade-offs

- **[Risk]** コンポーネント間での色選択ロジックの重複。
  - **Mitigation** 必要に応じて、カテゴリとテーマを渡すと適切な色を返すユーティリティ関数を `src/utils/` 等に作成する。
- **[Risk]** 既存データへの影響。
  - **Mitigation** `Category` 型の変更は定数定義と表示ロジックのみに影響し、DBに保存されている `categoryKey` には影響しないため、データ移行は不要。
